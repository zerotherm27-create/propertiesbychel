## Recommended execution order

**001 → 003 → 002**, though all three are independent and can be done in
any order or in parallel — there's no hard dependency between them. The
suggested order just front-loads the plan with the broadest surface area
(001 touches the most rules, so it's worth landing and feel-checking
first) and groups the two `css/site.css` + `.plisting`-adjacent plans
(001, 003) before the isolated `js/funnel.js` plan (002).

**Note on overlap**: 001 and 003 both touch `css/site.css` near the
`.plisting` block (001 wraps `css/site.css:308` in a media query; 003
inserts new rules after `css/site.css:317`). They don't edit the same
lines, but if applying both, apply them as separate commits/diffs rather
than concurrently on the same untracked working copy to keep the diffs
easy to review independently.

## Findings not turned into plans

From the full audit (see conversation history / prior findings table),
these were flagged but not selected for a plan in this round:

- Leftover `var(--dur)` hover transitions on `.link-line`,
  `.masthead__cta`, `.index-row__no`, `.funnel-choice` padding (LOW,
  easing/duration consolidation — five one-line token swaps).
- Hardcoded `220ms`/`.15s` durations that should reference `--dur-fast`
  (LOW, cohesion/tokens).
- `.dash-funnel__bar` animating `width` instead of `transform: scaleX()`
  at `--dur-slow` instead of `--dur` (MEDIUM, performance — dashboard is
  lower-traffic than the public site, deprioritized this round).
- Kanban card press feedback absent (missed opportunity, LOW).
- Dashboard trend bars have no reveal transition (missed opportunity,
  LOW).

Run `improve-animations plan <description>` to turn any of these into a
plan on demand, or re-run `improve-animations` bare for a fresh audit
once 001-003 have landed.
